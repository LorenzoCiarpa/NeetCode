# NeetCode Solutions

Repository delle mie soluzioni sincronizzate automaticamente da [NeetCode.io](https://neetcode.io)
tramite la funzione **GitHub Sync**. Il tracker qui sotto viene rigenerato a ogni push
da una GitHub Action, quindi resta sempre allineato alle submission.

## Struttura

Le soluzioni sono organizzate come le scrive NeetCode:

```
<topic-folder>/
  <problem-slug>/
    submission-0.py   ← primo tentativo
    submission-1.py   ← tentativo successivo
```

I file multipli per problema sono voluti: mostrano l'iterazione nel tempo, non solo
la versione finale.

## Come funziona il tracker

| File | Ruolo |
|------|-------|
| `utils/neetcode_catalog.json` | Catalogo: slug NeetCode → nome, difficoltà, pattern, liste |
| `utils/extra_problems.json` | Override e aggiunte manuali, vince sul catalogo |
| `utils/update_progress.py` | Scansiona le cartelle e riscrive il blocco `PROGRESS` |
| `.github/workflows/update-progress.yml` | Esegue lo script a ogni push |

### Cambiare lista tracciata

In cima a `utils/update_progress.py`:

```python
TRACK_LIST = "neetcode250"   # oppure "all" per il catalogo completo
```

Con `neetcode250` i problemi risolti fuori lista finiscono in una sezione
**Fuori lista**, senza sparire. Con `all` rientrano tutti nel conteggio.

### Aggiungere problemi mancanti

Se una soluzione non viene riconosciuta finisce nella sezione **Altro**. Per mapparla:

```bash
python utils/update_progress.py --report
```

Stampa gli slug sconosciuti già nel formato di `utils/extra_problems.json`: si incolla,
si correggono `name` / `difficulty` / `pattern`, e al push successivo vengono smistati
nella categoria giusta con i totali ricalcolati.

Per rigenerare in locale: `python utils/update_progress.py`
